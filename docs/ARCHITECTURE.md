# Архитектура

Один клуб, один сервер, одна база. Игроки остаются в общем чате Telegram. Организаторы правят людей, зал, расписание и оплату в веб-админке.

Подробности поведения — в [design.md](design.md).

## Где что живёт

```mermaid
flowchart LR
  players["Игроки"]
  organizers["Организаторы"]
  group["Общий чат"]
  dm["Личный чат с ботом"]
  browser["Браузер админки"]
  caddy["HTTPS"]
  app["Go: API, бот, планировщик, админка"]
  db[("Postgres")]

  players --> group
  organizers --> group
  organizers --> dm
  organizers --> browser
  group <--> app
  dm <--> app
  browser --> caddy --> app
  app --> db
```

Админка — это React, собранный в тот же процесс Go. Отдельного фронтенд-сервера нет. Бот и сайт делят одну базу.

## Что делает процесс

```mermaid
flowchart TB
  subgraph app ["Один процесс Go"]
    http["HTTP API"]
    static["Страницы админки"]
    hook["Вебхук Telegram"]
    clock["Планировщик, время Челябинска"]
  end
  db[("Postgres")]
  http --> db
  hook --> db
  clock --> db
  static --> http
```

Планировщик в пятницу спрашивает, запускать ли опрос, считает порог и по расписанию пишет общий долг. Вебхук принимает голоса и кнопку «Оплатил».

## Неделя

```mermaid
flowchart TD
  ask["Пятница 12:00. Вопрос в чат: запускать опрос?"]
  no{"Нет"}
  yes["Да"]
  poll["Опрос: Я буду / Я не буду"]
  early["Пятница 18:00. Если людей хватает: состав набрался, бронируйте зал"]
  remind["Суббота 12:00. Одно напоминание, если людей мало"]
  report["Суббота 18:00. Счёт. Голоса ещё можно менять"]
  snap["Начало тренировки. Состав фиксируется"]
  edit["Организатор отмечает, кто реально пришёл"]
  calc["Расчёт долей"]
  debt["В чат: кому сколько и куда переводить"]

  ask --> no
  ask --> yes
  no -->|"Да до начала тренировки"| yes
  yes --> poll
  poll --> early
  poll --> remind
  poll --> report
  report --> snap
  snap --> edit
  edit --> calc
  calc --> debt
```

«Нет» до появления опроса ставит пропуск. Следующее «Да» этот пропуск снимает. Уже опубликованный опрос кнопка «Нет» не убирает.

## Деньги

```mermaid
flowchart LR
  hall["Сумма зала"]
  student["Студент: фикс"]
  newbie["Новичок: 0"]
  rest["Обычные: остаток, округление вверх"]
  states["Не оплачено → заявка → оплачено"]

  hall --> student
  hall --> newbie
  hall --> rest
  rest --> states
  student --> states
```

Заявку в чате может нажать сам человек или тот, за кого он платит: Вика за пару с Денисом, Лена за пару с Димой. Оплаченной доля становится после подтверждения организатора в админке. Депозит Дениса закрывает целые доли сам, до сообщения в чат.

Раз в несколько дней, по умолчанию каждые 3 дня, бот пишет в чат один список: у кого какой долг и за какие тренировки. Интервал меняется в админке.

## Вход организатора

```mermaid
sequenceDiagram
  participant Org as Организатор
  participant Bot as Бот в личке
  participant Web as Админка

  Org->>Bot: Админка
  Bot->>Org: Одноразовая ссылка
  Org->>Web: Открывает ссылку
  Web->>Org: Вход на 30 дней
```

На компьютер, телефон и следующее устройство каждая ссылка своя. Пароля нет.
