# 012. Инструмент миграций схемы

Срез: Данные

Зависит от: 008

## Зачем

Схема должна накатываться одинаково локально и на сервере.

## Готово, когда

`make migrate` создаёт служебную таблицу goose. Повторный `make migrate` ничего не меняет. `make migrate-down` откатывает последнюю миграцию. `make migrate-status` показывает, какие файлы уже применены.

## Шаги

1. Подключить goose к `DATABASE_URL`. Вызов только из `Makefile`, отдельную команду в README не добавлять.
2. Каталог `migrations/` с первым пустым SQL, который можно откатить.
3. `make migrate` читает `.env` и вызывает `goose -dir migrations postgres "$$DATABASE_URL" up`. Рядом `make migrate-down` и `make migrate-status`.
4. Миграции только SQL-файлами, без изменения схемы из кода приложения при старте.

## Проверить

Два подряд `make migrate` завершаются без ошибки.
