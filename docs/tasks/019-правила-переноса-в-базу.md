# 019. Правила переноса в базу

Срез: Данные

Зависит от: 013, 014, 015, 018

## Зачем

История сезона должна оказаться в Postgres один раз и совпасть с согласованными исключениями. Первый прогон команды — локальная база. Ту же команду на боевой базе запускают только в задаче 047.

## Готово, когда

Повторный запуск импорта не дублирует людей и тренировки. Проверки из раздела «Проверить» проходят.

## Шаги

1. Создать 19 людей по именам шапки. «Илья » с пробелом склеить с «Илья».
2. Даниил: status student. Алиса и Саша: newcomer, newcomer_visits = 2.
3. Вика.payer = Денис, Лена.payer = Дима.
4. Депозит Дениса 4500.
5. Телефоны и пометки банка перенести из локальной выгрузки в карточки. Номера в код и в документацию не писать. Если у одного человека в строках два разных номера, в карточку берётся тот, который подтвердит организатор.
6. Строки без состава и без суммы не вставлять. Список дат зафиксирован в `docs/design.md`.
7. Остальные строки: session source=import, starts_at в челябинской зоне, время 17:00 если в листе времени нет. День недели брать из колонки «Дн», если он есть.
8. Инвестор по имени колонки C. Доли из чисел ячеек. Зелёная заливка `#00FF00` → payment_status paid, paid_via manual.
9. Если сумма долей не равна залу, shares_mismatch=true и короткая заметка с обеими суммами.
10. 24.10.2025 и 31.10.2025: доли 444, mismatch, заметка про 4 ₽.
11. 18.10 и 25.10: Алиса и Саша amount 0, kind newcomer. Чужие числа не менять.
12. 27.09.2026: hall 4500, Даниил 200 student, Дима, Лена, Денис, Вика, Паша, Леша, Ваня по 614 regular. Паша paid via investor. mismatch 4498 против 4500.
13. Идемпотентность: ключ тренировки — дата. Повтор не создаёт вторую.
14. Ники импорт не выдумывает.

## Проверить

Запросы: людей 19; тренировок 48; депозит Дениса 4500; у Алисы две явки и обе доли 0; 27.09 содержит 8 долей и оплачен только Паша; пустой 07.09.2025 отсутствует.
