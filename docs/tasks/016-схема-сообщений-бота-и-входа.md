# 016. Схема сообщений бота и входа

Срез: Данные

Зависит от: 015

## Зачем

Повторный запуск процесса не должен создавать второй опрос. Сессии входа живут отдельно на устройство.

## Готово, когда

Таблицы есть. Токен ссылки хранится только хешем.

## Шаги

1. `launch_prompts`: session_id unique, chat_id, message_id, state (`open`, `yes`, `no`).
2. `polls`: session_id unique, telegram_poll_id, chat_id, message_id, opened_at, snapshotted_at nullable.
3. `debt_posts`: session_id unique, chat_id, message_id.
4. `reminder_posts`: id, sent_on date. Нужна, чтобы в один календарный день не отправить два дайджеста.
5. `magic_links`: id, person_id, token_hash, expires_at, used_at nullable.
6. `auth_sessions`: id, person_id, token_hash, expires_at, revoked_at nullable. Одна строка на устройство.
7. Индекс по token_hash.

## Проверить

Повторная вставка второго poll на ту же session_id падает.
