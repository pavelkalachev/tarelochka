# 039. Расчёт при подтверждении состава

Срез: Админка

Зависит от: 017, 028, 038

## Зачем

Доли появляются только после кнопки «Состав подтверждён».

## Готово, когда

Подтверждение вызывает калькулятор, пишет shares и student_price_rubles тренировки. Повторное подтверждение после правки состава перезаписывает неоплаченные доли. Оплаченную долю не затирать молча: если человек снят после оплаты, вернуть ошибку организатору.

## Шаги

1. Кнопка на странице вызывает `POST /api/sessions/{id}/confirm`.
2. В состав входят attended=true и сопоставленные. Несопоставленные блокируют подтверждение с текстом, кого связать.
3. Тип берётся из текущего статуса человека. Цена студента из settings на этот момент пишется в session.
4. Новичку, который впервые подтверждён на этой тренировке, увеличить newcomer_visits на 1, если эта явка ещё не была засчитана. Повторное подтверждение той же тренировки счётчик не увеличивает второй раз.
5. Исторические импортированные доли не прогонять через калькулятор. confirm для source=import не пересчитывает amounts, если организатор явно не нажал отдельное «пересчитать». Отдельной кнопки пересчёта истории нет.
6. Для bot-тренировки записать shares. Инвестора пометить paid via investor.
7. Ошибку калькулятора показать на странице и в логе. Доли не писать.
8. После успеха страница показывает доли.

## Проверить

Тест 6 обычных, студент 200, зал 4500 даёт 717. Повторный confirm не удваивает newcomer_visits.
