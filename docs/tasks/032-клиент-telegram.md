# 032. Клиент Telegram

Срез: Бот

Зависит от: 001, 009, 016

## Зачем

Один процесс принимает вебхук и вызывает Bot API.

## Готово, когда

Локальный процесс с тестовым токеном получает обновления из своего чата через long polling. `POST /telegram/webhook` без секретного заголовка получает 401. Вебхук на этом шаге не включается.

## Шаги

1. Пакет `internal/bot`: SendMessage, EditMessageText, AnswerCallbackQuery, SendPoll, StopPoll не обязателен.
2. `POST /telegram/webhook`. Секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`, значение из `TELEGRAM_WEBHOOK_SECRET`.
3. Разбор callback_query и poll_answer. Пока только лог типа update.
4. Если `TELEGRAM_WEBHOOK_URL` пуст, при старте вызвать `deleteWebhook` и читать `getUpdates` тестовым токеном. Так локальная разработка не требует домена. Боевой токен в этот режим не подставлять: `deleteWebhook` боевого бота с машины разработчика запрещён.
5. Если `TELEGRAM_WEBHOOK_URL` задан, long polling не запускать. Этот путь включает задача 046 на сервере.
6. Ручной `POST /telegram/webhook` оставить для проверки секрета без Telegram.
7. Таймаут исходящих вызовов Telegram 10 секунд. Ответ на callback всегда уходит, чтобы у пользователя не крутилась кнопка.

## Проверить

Запрос без секрета не доходит до обработчика логики. Сообщение в тестовом чате при пустом `TELEGRAM_WEBHOOK_URL` появляется в логе локального процесса.
