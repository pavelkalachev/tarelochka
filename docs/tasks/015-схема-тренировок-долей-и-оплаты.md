# 015. Схема тренировок, долей и оплаты

Срез: Данные

Зависит от: 014

## Зачем

Тренировка отделена от слота: слот порождает даты, тренировка хранит факт вечера.

## Готово, когда

Одна тренировка не может иметь две доли одного человека. Состояние оплаты только из трёх значений.

## Шаги

1. `sessions`: id, club_id, slot_id nullable, gym_id nullable, starts_at timestamptz, status (`planned`, `polling`, `skip`, `played`), hall_amount_rubles int nullable, investor_id nullable, shares_mismatch bool default false, mismatch_note text, source (`import`, `bot`), student_price_rubles int nullable, roster_confirmed_at timestamptz nullable.
2. Статус `played` ставится подтверждением состава. `skip` ставит организатор или кнопка «Нет», пока опроса нет.
3. `attendances`: session_id, person_id nullable, coming bool, attended bool, unmatched_label text, unmatched_username text, unmatched_user_id bigint. Либо person_id, либо несопоставленная подпись.
4. `shares`: session_id, person_id, amount_rubles int nullable, kind (`regular`, `student`, `newcomer`), payment_status (`unpaid`, `claimed`, `paid`), paid_via (`manual`, `claim`, `deposit`, `investor`) nullable. Unique (session_id, person_id).
5. `payment_claims`: id, session_id, payer_id, pressed_by_person_id, status (`pending`, `confirmed`, `rejected`), created_at. На одну пару и одну тренировку не больше одной pending-заявки.
6. amount_rubles null значит «был, суммы нет». Для переноса таких строк почти не останется: плюсы мы считаем.

## Проверить

Две доли одного человека на одной тренировке вставить нельзя.
