# 013. Схема людей и клуба

Срез: Данные

Зависит от: 012

## Зачем

Люди, ники, статусы, плательщики, депозиты и роль организатора — основание всех остальных таблиц.

## Готово, когда

Миграция создаёт таблицы и ограничения. Нельзя вставить двух людей с одним и тем же именем шапки. Нельзя сделать человека плательщиком самого себя.

## Шаги

1. Таблица `club`: одна строка, название «Алтимат. Челябинск», часовой пояс `Asia/Yekaterinburg`.
2. Таблица `people`: id, club_id, name, status (`regular`, `student`, `newcomer`), newcomer_visits int not null default 0, telegram_username nullable, telegram_user_id bigint nullable unique, phone nullable, bank_note nullable, payer_id nullable references people, is_organizer bool, active bool.
3. Уникальность имени в рамках клуба.
4. `payer_id` не равен своему id. Проверка в SQL.
5. Таблица `deposits`: person_id primary key, balance_rubles int not null check >= 0.
6. Индекс по `telegram_username` в нижнем регистре. Ник хранить без `@`, сравнивать без учёта регистра.

## Проверить

В psql видны таблицы. Попытка поставить payer_id = id падает.
