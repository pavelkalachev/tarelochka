# 008. Postgres локально

Срез: Каркас

Зависит от: 007

## Зачем

Схему и перенос таблицы нужно проверять на своей машине до сервера.

## Готово, когда

`make docker.start` поднимает compose, и вместе с ним Postgres. Команда дожидается готовности. Go-процесс подключается по `DATABASE_URL` из `.env` и пишет в лог, что соединение есть. Схему этот запуск не создаёт.

## Шаги

1. `docker-compose.yml` в корне: сервис `postgres`, образ официальный, порт 5432 на localhost, volume для данных, пользователь и пароль только из `.env`. Healthcheck, чтобы `make docker.start` дождался приёма соединений.
2. База, например `tarelochka`. В каталог инициализации образа SQL не класть: таблицы появятся только из `migrations/`.
3. В `cmd/server` на старте открыть пул `pgxpool` и выполнить `select 1`.
4. В README подъём и остановка: `make docker.start` и `make docker.stop`. Отдельной команды только для базы нет.

## Проверить

После перезапуска compose данные volume на месте. `select 1` в логе успешен.
